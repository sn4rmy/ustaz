# Требования предмета: командный проект

Источник: файл Milestone 1 от преподавателя.

## О проекте

Команда за семестр создаёт работающий веб- или мобильный продукт с
оплатой, внешними API, AI-агентом и ML-модулем, и защищает его на РК2 /
эндтерме. Тему команда выбирает сама. Желательно (но не обязательно),
чтобы проект был связан с дипломной работой одного из участников: тогда
за семестр команда получает работающий прототип, который можно
использовать в практической части диплома. В любом случае продукт должен
решать реальную проблему реальных пользователей.

**Примеры тем:** возьмите тему диплома и сделайте по ней продукт.
Например: диплом про рекомендательные системы → платформа с
персональными рекомендациями; про анализ тональности → сервис отзывов с
автоматической модерацией; про прогнозирование → магазин или склад с
прогнозом спроса; про медицину / образование / финтех → соответствующий
сервис с AI-помощником; про кибербезопасность → система с обнаружением
аномалий. Если тема диплома не подходит под формат, можно выбрать свою:
маркетплейс репетиторов, сервис бронирования, финансовый трекер и т.п.
To-do листы и копии учебных туториалов не принимаются.

**Команда:** 3–5 человек. У каждого участника есть роль (Team Lead / PM,
Backend, Frontend, ML / AI, DevOps / QA) и видимый вклад в GitHub. Один
человек может совмещать роли.

| Этап        | Срок           | Что сдаётся                                            | Формат сдачи            | Оценка           |
|-------------|----------------|--------------------------------------------------------|-------------------------|------------------|
| Milestone 1 | 1–2 недели     | Идея, команда, план, GitHub, Gantt                     | Питч 5–7 минут + ссылки | из 100           |
| Milestone 2 | 1–2 недели     | Дизайн, backend, API, оплата, Docker, AI-агент         | Демо 10 минут + код     | из 100           |
| Milestone 3 | 1–2 недели     | ML-модуль, финальный продукт, защита на РК2 / эндтерме | Защита 15 минут + Q&A   | из 100           |
| **Итог**    | **3–6 недель** |                                                        |                         | **среднее трёх** |

**Итоговая оценка за проект = (Milestone 1 + Milestone 2 + Milestone 3)
/ 3.** Например: 85, 78 и 92 → (85 + 78 + 92) / 3 = 85 баллов.

На каждый milestone даётся 1–2 недели, точные даты объявляет
преподаватель; все материалы загружаются до 23:59 дня дедлайна.

## Milestone 1 — Идея и планирование (100 баллов, 1–2 недели)

Цель: команда доказывает, что понимает, что строит, для кого и как
успеет по срокам. Кода пока минимум, главное — план.

### Что должно быть

1.  **Команда и роли** — ФИО, роль каждого, зона ответственности,
    контакт тимлида.
2.  **Идея и проблема** — какую проблему решаем, целевая аудитория, 2–3
    конкурента и чем мы отличаемся. Если проект связан с дипломом —
    указать тему диплома, автора и какую часть диплома закрывает проект.
3.  **Описание MVP** — 5–8 ключевых функций в виде user stories («Как
    пользователь, я хочу…, чтобы…»). Отдельно указать: где будет оплата,
    где AI-агент, где ML-модель.
4.  **Технологический стек** — frontend, backend, БД, платёжная система,
    LLM / фреймворк для агента, ML-библиотеки — с коротким обоснованием
    выбора.
5.  **Черновая архитектура** — схема компонентов (frontend → backend →
    БД / внешние API / AI / ML), можно в draw.io или Excalidraw.
6.  **GitHub-репозиторий** — создан, преподаватель добавлен как
    collaborator; README с названием, описанием, составом команды и
    стеком; ветки `main` и `dev`; `.gitignore`; структура папок
    (`frontend/`, `backend/`, `ml/`, `docs/`).
7.  **Таск-трекер** — GitHub Projects, Jira или Trello; задачи разбиты и
    назначены на людей на весь Milestone 2.
8.  **Диаграмма Ганта** — все три milestone, задачи по неделям,
    ответственный на каждую задачу, зависимости между задачами.
9.  **Риски** — 2–3 риска (например, «нет данных для модели») и план Б.
10. **Презентация-питч** — 8–12 слайдов, выступление 5–7 минут.

### Сдать

- Ссылка на GitHub, таск-трекер и диаграмму Ганта
- Презентация (PDF) в папке `docs/` репозитория

| Критерий                                             | Баллы   |
|------------------------------------------------------|---------|
| Идея, проблема, анализ конкурентов, связь с дипломом | 20      |
| MVP и user stories                                   | 15      |

## Общие правила

- **Шкала.** Каждый milestone оценивается по 100 баллам; итог за проект
  — среднее арифметическое трёх оценок. Оценка за milestone с учётом
  бонусов не может быть выше 100.
- **Индивидуальная оценка.** Балл команды корректируется по вкладу
  каждого: коммиты, PR, задачи в трекере, ответы на вопросы. Участник
  без вклада может получить 0.
- **Опоздание.** Минус 10 баллов за каждые сутки; после 3 суток
  milestone не принимается.
- **Использование AI-инструментов** (Copilot, Claude, ChatGPT) при
  написании кода разрешено, но каждый обязан объяснить свой код на
  защите.
- **Плагиат.** Скопированный чужой проект или репозиторий с одним
  гигантским коммитом в последний день = 0 за milestone.
- **Смена идеи** после Milestone 1 только по согласованию с
  преподавателем.
