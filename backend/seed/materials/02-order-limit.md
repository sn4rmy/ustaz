# Конспект: сортировка и LIMIT

Примеры используют учебную базу из таблиц `departments (id, name)` и `employees (id, name, department_id, salary, hire_date)`. Диалект — SQLite.

## Зачем нужен ORDER BY

Без `ORDER BY` порядок строк в результате не гарантирован. Сегодня строки могут прийти в порядке добавления, а после изменения таблицы или индекса — в другом. Если порядок важен, его нужно задать явно.

```sql
SELECT name, salary
FROM employees
ORDER BY salary;
```

По умолчанию сортировка идёт по возрастанию (`ASC`). Для убывания пишут `DESC`:

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

## Несколько ключей сортировки

Можно сортировать по нескольким столбцам. Второй столбец учитывается только для строк, у которых первый совпадает. У каждого столбца своё направление.

```sql
SELECT department_id, name, salary
FROM employees
ORDER BY department_id ASC, salary DESC;
```

Здесь сотрудники сгруппированы по отделам, а внутри отдела идут от большей зарплаты к меньшей.

## Сортировка по выражению и псевдониму

В `ORDER BY` можно писать выражения и псевдонимы из `SELECT`. `ORDER BY` выполняется после `SELECT`, поэтому псевдоним к этому моменту уже существует.

```sql
SELECT name, salary * 12 AS year_salary
FROM employees
ORDER BY year_salary DESC;
```

Можно сослаться и на номер столбца (`ORDER BY 2`), но так запрос хуже читается, и при изменении списка столбцов он ломается.

## NULL при сортировке

В SQLite `NULL` считается меньше любого значения. При `ASC` строки с `NULL` идут первыми, при `DESC` — последними. С версии SQLite 3.30 порядок можно задать явно:

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC NULLS LAST;
```

## Строки и регистр

Текст сортируется по кодам символов: заглавные буквы идут раньше строчных, латиница раньше кириллицы. `COLLATE NOCASE` отключает учёт регистра, но только для латиницы.

## LIMIT: первые N строк

`LIMIT` ограничивает число строк в результате. Вместе с `ORDER BY` он даёт запросы вида «топ-N»:

```sql
-- три самые высокие зарплаты
SELECT name, salary
FROM employees
ORDER BY salary DESC
LIMIT 3;
```

`LIMIT` без `ORDER BY` возвращает какие-то N строк, и неизвестно, какие именно. Это частая ошибка.

В SQLite нет `TOP` (как в SQL Server) и нет `FETCH FIRST` (как в стандарте). Используется только `LIMIT`.

## OFFSET: пропустить строки

`OFFSET` пропускает заданное число строк. Так делают постраничный вывод: страница номер `p` (с единицы) по `n` строк — это `LIMIT n OFFSET (p - 1) * n`.

```sql
-- вторая страница по 10 сотрудников, по алфавиту
SELECT name
FROM employees
ORDER BY name
LIMIT 10 OFFSET 10;
```

В SQLite есть и короткая запись `LIMIT 10, 10`: первое число — смещение, второе — количество. Её легко перепутать, поэтому лучше писать `OFFSET` явно.

## Одинаковые значения на границе

Если у нескольких сотрудников одинаковая зарплата, `ORDER BY salary DESC LIMIT 3` вернёт трёх из них, и каких именно — не определено. Чтобы результат был стабильным, добавьте второй ключ, например `id`:

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC, id
LIMIT 3;
```

## Порядок выполнения

`FROM` → `WHERE` → `SELECT` → `ORDER BY` → `LIMIT/OFFSET`. Сначала отбираются строки, потом сортируются, и только потом от отсортированного результата отрезаются первые N.

```sql
-- самый «новый» сотрудник отдела 1
SELECT name, hire_date
FROM employees
WHERE department_id = 1
ORDER BY hire_date DESC
LIMIT 1;
```

## Частые ошибки

- `LIMIT` без `ORDER BY`.
- Ожидание, что строки придут «в порядке добавления».
- Перепутанные числа в `LIMIT a, b`.
- Забытый второй ключ сортировки при одинаковых значениях.
